== v1.0.31.48 — 2026-10-17

=== Added

* **Sous-commande `watermark`** : expose en standalone le même
  moteur que la section `watermark:` du YAML de `build`, pour
  filigraner un PDF à la volée sans passer par un livret.
  Délègue à `Watermark.apply` du shard aloli-crystal/watermark
  (déjà dépendance pour `build`).
+
[source,bash]
----
combine-pdf watermark rib.pdf -t "CONFIDENTIEL" -o rib-wm.pdf
combine-pdf watermark rib.pdf -t "..." -s tiled -i          # in-place
combine-pdf watermark rib.pdf -t "..." --opacity 0.1 --rotation 30
----
+
Styles : diagonal (défaut), tiled, header, footer, center.
Flags : `-t`/`--text`, `-s`/`--style`, `--opacity`, `--rotation`,
`--wm-color R,G,B`, `--wm-font-size N`.
+
Combiné avec `rasterize` → protection anti-falsification à la
DossierFacile :
+
[source,bash]
----
combine-pdf watermark rib.pdf -t "..." -s tiled -i
combine-pdf rasterize rib.pdf -i
----

=== Fixed

* **`combine-pdf help <sub>`** reconnaît désormais `merge`,
  `assemble`, `number`, `watermark`, `sign` et `verify` dans
  `valid_subs`. Avant, `combine-pdf help merge` affichait
  « Aide indisponible pour « merge » » alors que la sous-commande
  existait bel et bien (section « Sous-commandes historiques »
  du banner). Le filtre d'aide est donc désormais cohérent avec
  les sous-commandes réellement disponibles.

=== Note

* Pour un rendu correct du filigrane sur des PDFs sources dont
  les `/Resources /Font` ne contiennent pas Helvetica (cas des
  RIB Caisse d'Épargne et autres documents formulaires), il faut
  **watermark >= 0.1.8** qui déclare `/Helvetica` dans les
  Resources de la page avant d'injecter le stream. Les versions
  antérieures émettent un stream qui référence une fonte non
  déclarée → le viewer skip silencieusement et le filigrane
  reste invisible. Contrainte conservée à `"~> 0.1.5"` pour
  compatibilité, mais `shards update watermark` au préalable
  est recommandé.

== v1.0.31.45 — 2026-06-28

=== Added

* **Ouverture automatique du livret après `build`** quand la sortie
  est un terminal interactif. Évite le « lancer `build` → chercher
  le PDF dans le Finder → double-cliquer » à chaque itération.
+
[source,bash]
----
combine-pdf            # → build + ouvre dans Aperçu
combine-pdf build      # idem (forme explicite)
combine-pdf --no-open  # build, ne pas ouvrir
----
+
Comportement :
+
* En **terminal interactif** (STDOUT + STDERR sont des TTY), le
  PDF produit est lancé en arrière-plan via `open` (macOS) ou
  `xdg-open` (Linux/BSD).
* En **non-interactif** (cron, CI, redirection vers pipe ou
  fichier, sortie capturée), aucune ouverture — pas de surprise
  dans les scripts.
* `--no-open` force off même en TTY.
* Échec silencieux si `open`/`xdg-open` introuvable ou si le
  process retourne non-zéro : le PDF est sur disque, c'est
  l'essentiel.

S'applique **uniquement à `build`** (cas usage : itérer sur un
livret et vérifier visuellement). Les autres sous-commandes
(`merge`, `assemble`, `compress`, `gs`, `encrypt`, `decrypt`,
`rasterize`) ne sont pas concernées — leur sortie est souvent
une étape intermédiaire d'un pipeline.

== v1.0.31.44 — 2026-06-23

=== Added

* **Sous-commande `rasterize`** : convertit chaque page d'un PDF en
  image JPEG plein page (via Ghostscript) puis réembarque le tout
  dans un nouveau PDF. Anti-extraction / anti-falsification —
  pattern observé chez DossierFacile pour les RIB protégés où
  TOUT le document est un seul JPEG par page, rendant le texte
  non-extractible et un filigrane indissociable du contenu.
+
[source,bash]
----
combine-pdf rasterize rib.pdf -o rib-protege.pdf
combine-pdf rasterize rib.pdf -i                # in-place
combine-pdf rasterize rib.pdf --dpi 300 --quality 95
----
+
Pipeline interne :
+
. `gs -sDEVICE=jpeg -r{dpi} -dJPEGQ={quality}` rend chaque page.
. Les dimensions de chaque page source sont préservées (A4,
  Letter, custom — lues via `PDF::Reader` avant la rastérisation).
. Le nouveau PDF embarque les JPEG en `PDF::Page#image` plein page.
. Le `/Producer` est tagué `combine-pdf X.Y.Z (rasterized)`
  pour la traçabilité.

=== Options

* **`--dpi=N`** — résolution de rendu (défaut 200 dpi). 150 = écran,
  300 = imprimable.
* **`--quality=Q`** — qualité JPEG 0-100 (défaut 85).
* **`-i` / `--in-place`** — réécrit le fichier d'entrée via .tmp atomique.
* **`-o FICHIER`** — chemin de sortie explicite (sinon `<source>-rasterized.pdf`).

=== Compromis assumés

* Texte non extractible (pas de copier-coller, pas d'OCR
  immédiat) — mauvais pour l'accessibilité, voulu pour
  l'anti-falsification.
* Taille fichier nettement supérieure à un PDF vectoriel
  équivalent (RIB 200 Ko → 460 Ko à 200 dpi qualité 85).

=== Specs

* Nouveau module `CombinePDF::Rasterizer` + 4 specs
  (pipeline 2 pages A4, préservation dimensions Letter,
  traçabilité Producer, cache `ghostscript_available?`).
  Skip si `gs` absent.

== v1.0.31.43 — 2026-06-16

=== Added

* **Détecteur `/Rotate` + cuisson automatique via `qpdf --flatten-rotation`.**
  Aperçu macOS (et la plupart des viewers PDF) tournent une page
  scannée à l'envers en posant un tag `/Rotate 180` sur le dict de
  la page, sans réécrire les opérateurs de contenu. Visuellement
  correct dans le viewer, mais l'assemblage naïf de
  `combine-pdf` ignorait ce tag et embarquait la page à
  l'envers dans le PDF final.
+
  Désormais, `Merger#add` détecte les pages avec `/Rotate ≠ 0` via
  le nouvel accesseur `PDF::ReaderPage#rotate` (shard `pdf` 1.20.2)
  et, si `qpdf` est dans le PATH, applique `qpdf --flatten-rotation`
  sur un fichier temporaire avant la fusion. Un message
  informatif est écrit sur `STDERR` :
  `✓ <path> : cuit /Rotate sur N page(s) (7).`
+
  Si `qpdf` n'est pas disponible, un avertissement est émis et le
  pipeline continue avec le fichier original (fallback gracieux,
  pas de crash). S'applique à `build`, `merge`, `assemble`.

=== Options

* **`-R`, `--no-flatten-rotation`** — désactive le pré-traitement.
  Pour les rares cas où l'on veut préserver le tag `/Rotate` du
  PDF source (par ex. test de conformité, transfert vers un outil
  qui interprète `/Rotate`).

=== Specs

* Nouveau module `CombinePDF::RotationFlattener` + 8 specs
  (détection, cuisson, fallback sans qpdf, intégration `Merger`).
* Le shard `pdf` 1.20.2 gagne `PDF::ReaderPage#rotate : Int32`
  (héritable depuis `/Pages`, normalisé en `[0, 360[`).

== v1.0.31.41 — 2026-06-16

=== Added

* **Proposition interactive de créer `.combine-pdf.yml`**
  quand on lance la commande dans un dossier qui n'en contient pas.
  Avant : message d'erreur sec « Pour démarrer : combine-pdf init ».
  Maintenant : prompt « Voulez-vous le créer maintenant (équivalent

  ou STDERR), le comportement antérieur est strictement préservé :
  message d'erreur + sortie avec code 1, pour ne pas casser les
  scripts existants. Un EOF (Ctrl-D) au prompt = annulation
  explicite (code 1), pas acceptation par défaut.

== v1.0.31.38 — 2026-06-05

=== Added

* **Sous-commandes `sign` / `verify`** — signer (PAdES) ou vérifier un
  document directement depuis combine-pdf, l'étape naturelle après
  `merge` / `assemble`. Ce sont de fins relais vers le binaire `pdf-sign`
  de `aloli-crystal/pdf-signature` : tout ce qui suit le verbe lui est
  transmis tel quel, donc toute la surface de drapeaux (niveaux

  n'apparaît dans argv.

  cherche `pdf-sign` (via `$COMBINE_PDF_PDFSIG` ou le `PATH`) et JAMAIS
  le `pdfsig` de poppler (outil différent). Nouveau module
  `CombinePDF::Signer` ; specs de résolution.

== v1.0.31.37 — 2026-05-08

=== Added

* **Flag `-L` / `--linearize` sur la sous-commande `compress`**
  pour produire un PDF *Fast Web View* (ISO 32000-1 § F).
+
[source,shell]
----
combine-pdf compress livret.pdf -L              # → livret-compressed.pdf linéarisé
combine-pdf compress livret.pdf -i --backup -L  # in-place
----
+
Implémentation : shell-out à `qpdf --linearize` après la passe de
compression Flate. Choisi pragmatiquement plutôt qu'une
implémentation native (estimée 2-4 semaines + ~2000 lignes ;
shell-out qpdf = robustesse 100 % du jour 1, dépendance externe
acceptable au même titre que `gs` pour `--deep`).
+
**À ne pas combiner avec un PDF déjà signé** (PAdES) : la
réorganisation des octets invalide la signature. La doc
recommande de linéariser AVANT de signer.
+
Le résultat est vérifiable avec `pdfinfo` :
`Optimized: no` → `Optimized: yes`.

* `CombinePDF::Compressor.qpdf_available?` — méthode publique pour
  tester la présence de `qpdf` dans le PATH avant d'appeler
  `compress(linearize: true)`. Retourne `Bool`, mise en cache
  après le premier appel.

* Spec d'intégration `linearize_spec.cr` (3 specs, skip si qpdf
  non installé). Vérifie la présence de `/Linearized` dans les
  premiers octets du PDF produit.

== v1.0.31.35 — 2026-05-08

=== Fixed

* **`/Author` et `/Title` du PDF généré : mojibake sur les caractères
  accentués.** `pdfinfo` affichait « Philippe NÃ©nert » au lieu de

combine-pdf) avait le bug.

== v1.0.31.34 — 2026-05-07

=== Fixed

* **`/Producer` du PDF généré inscrivait toujours « 1.0.31.26 ».**
  La constante `CombinePDF::VERSION` était hardcodée dans
  `src/combine_pdf/version.cr` et n'était pas mise à jour lors des
  releases (oubli systématique dans le workflow de bump). Conséquence :
  toutes les versions de v1.0.31.27 à v1.0.31.33 produisaient des PDFs
  dont le `/Producer` indiquait « combine-pdf 1.0.31.26 », et
  un binaire compilé localement à partir de la dernière production
  affichait `combine-pdf --version` → `1.0.31.26`.
+
Fix : `VERSION` est désormais lue **au compile-time** directement
depuis `shard.yml` via le macro `read_file`. Plus jamais de
désynchronisation possible entre la source de vérité (`shard.yml`)
et la constante embarquée dans le binaire.

* **Spec de non-régression** : `spec/version_spec.cr` parse `shard.yml`
  à l'exécution et compare `CombinePDF::VERSION` à la valeur YAML —
  garantit que la lecture macro reste cohérente.

=== Notes

Si vous aviez compilé localement une version récente de
`combine-pdf` (binaire `~/.local/bin/combine-pdf`
typiquement) et constaté un `--version` figé à 1.0.31.26, c'est ce
bug. Recompilez à partir de v1.0.31.34.

== v1.0.31.19 — 2026-04-29

=== Fixed

* **Numbering rendered upside-down or invisible on some pages.**
  When a source PDF opens its content stream with a non-trivial CTM
  (e.g. `0.75 0 0 -0.75 0 841.92 cm` for a Y-flip + 0.75× scale,

  well-formed PDFs).

  `[]` arrays, `<<>>` dicts, `%` comments and tracks q/Q depth.

=== Fixed

* `CombinePDF::PDF` wraps the existing `Merger` ; ordering

* `Merger#write` is now idempotent: a snapshot of `@objects` and

  `save` then `to_pdf` (or vice-versa) on the same instance
  produces deterministic byte streams.
* Two new `Merger` properties — `metadata_title`, `metadata_author`

== v0.2.0 — 2026-04-26

**Multi-PDF merging shipped — the headline feature.** This is what
the upstream Ruby gem `combine_pdf` is famous for, and it's now
available in Crystal too.

Three new building blocks :

* `CombinePDF.merge(inputs : Array(String), output : String)` —
  concatenates several PDFs into one. Pages are taken in input
  order. Object IDs are renumbered to avoid collisions between
  sources, references rewritten recursively (Dictionary → Array →
  Stream metadata). MediaBox of every page preserved (mix A4 +
  Letter + A3 cohabits without normalisation).
* `CombinePDF.assemble(inputs, output, options)` — end-to-end
  booklet assembly: merges N PDFs, then numbers the result with
  partition sizes auto-detected from the input page counts. The
  workflow for a music score booklet of partitions of 1, 2 or N
  pages.
* CLI sub-commands `merge` and `assemble` :

  ----
  combine-pdf merge p1.pdf p2.pdf p3.pdf -o livret.pdf
  combine-pdf assemble p1.pdf p2.pdf p3.pdf -o livret.pdf
  ----

Implementation details :

* New `CombinePDF::Merger` class : reads each source via
  `PDF::Reader`, forces lazy materialisation of every indirect
  object via `Reader#resolve` over the whole xref, then renumbers
  & remaps recursively.
* New `CombinePDF::MergedDocumentWriter` : minimal PDF writer
  (header + indirect objects + xref + trailer). Bypasses
  `PDF::Document` because the latter is coupled to its in-memory
  pages and doesn't apply to external page injection.
* Dropped `/Filter`, `/DecodeParms`, `/Length` from copied stream
  dicts — the Reader stores decoded bytes but leaves the original
  filter declaration, which would make the next parser try to
  Flate-decode already-clear bytes.
* No deduplication of common resources (fonts, images) yet — the
  output is correct but slightly larger than what an optimising
  merger would produce. Targeted for v0.3.

Tests : 13 examples (2 unit + 11 integration), all green via real
`PDF::Reader.open` round-trips.

== v0.1.0 — 2026-04-25

First public release. Pure-Crystal PDF page numbering, designed for
booklet assembly use cases (music score collections, course handouts,
…). Inspired by the Ruby gem
https://github.com/boazsegev/combine_pdf[combine_pdf] — fixes its
US Letter coordinate hardcoding and adds *partition-aware*
intra-numbering, which the upstream gem does not support.

* **Global page numbering** in the bottom-right corner, format
  customisable via `Options#global_format` (placeholders `%page%`
  and `%total%`, default `"%page%/%total%"`).
* **Intra-partition numbering** in the top-left corner, format
  customisable via `Options#partition_format`. Shown only when the
  partition spans more than one page (configurable via
  `hide_partition_when_single`).
* **A4-aware**, Letter-aware, A3-aware: coordinates are derived
  from each page's actual `MediaBox`, no per-format flag needed.
* **Skip pages** option (e.g. `--skip 1` to leave the cover
  unmarked).
* CLI sub-command `number` with short and long flags for every
  option.
* API: `CombinePDF.number(input, output, partitions, options)`.
* Bilingual README (EN + FR), CHANGELOG bilingue, ameba lint, CI
  GitHub Actions.
